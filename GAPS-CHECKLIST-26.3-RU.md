## Datapack: статус трёх запрошенных возможностей

| Возможность | Статус | Подтверждённая граница |
|---|---|---|
| Полный `/reload` | Частично | Загружаются функции, function tags, game rules, permission groups; нет рецептов, loot tables, advancements, registry tags; нет общей транзакции. |
| `/datapack enable` / `disable` | Реализованы | Команды с placement (first/last/after/before), chat links, refusal messages, персистентность в `level.toml`. |
| Онлайн-синхронизация datapack | Частично | Функции и function tags перезагружаются; recipes, loot tables, advancements, теги реестров не обновляются атомарно. |

**Завершено 2 из 3 (частично 1).** Точечные тесты функций не доказывают полный runtime-pariтет всех типов ресурсов.

## Подтверждённые проблемы и блокеры

- `steel-core/src/command/builtins/datapack.rs`: `/datapack enable|disable|list|create|reload` реализованы; `steel-core/src/server/datapacks.rs` загружает функции, function tags, внешние пакеты из `world/datapacks`. Остаётся: pack.mcmeta pack_format, symlinks, $ макросы, overlays/фильтры, атомарное обновление runtime-реестров.
- `AGENTS.md` запрещает проектировать runtime-загрузку datapack JSON и одновременно требует полного vanilla-поведения. Пользователь разрешил разрабатывать поддержку runtime datapack при условии сохранения оптимизации и многопоточности. Нужны проверка целевого vanilla-источника и проектирование безопасной публикации снимка без блокирования игровых тиков; совместимость и производительность пока не доказаны.
- После разрешения пользователя на Java в Actions генератор `./update-minecraft-src.sh` успешно создал исходник 26.3 ([run 44926675892](https://github.com/Greston897/SteelMC/actions/runs/44926675892), commit GitCraft `83c9c738a181c342f2a0ebc1f2eea3369d00f59e`). Из артефакта проверенной контрольной суммы извлечён `minecraft-src/minecraft/src/net/minecraft/`; остальные ресурсы полного архива локально не извлекались. Сам исходник в Git SteelMC не добавляется.
- Доступен независимый временный эталон блоков из официального сервера 26.3: [диагностика 44926701914](https://github.com/Greston897/SteelMC/actions/runs/44926701914) сверила все семь захваченных хешей с существующим fixture и показала различия в цветах, кактусах и сундуках. В том снимке тест падал на 7/2500 чанков; сама диагностика была локализацией, а не исправлением. Эталон остаётся артефактом Actions, а не вручную созданным fixture в репозитории. Попытка трассировки записей в [44931206250](https://github.com/Greston897/SteelMC/actions/runs/44931206250) не выдала записей; причину конкретной генерационной ошибки она не установила.
- Базовые результаты на `376ff3e`: Lint, Test, Flint selected, Build Report и Live Smoke прошли; Vanilla Evidence `flint-all` прошёл в этом запуске, но `chunk-stages` вновь выявил 7/2500 расхождений Overworld/features. Это не отменяет предыдущих периодических сбоев на моркови/кактусе и не доказывает все 19 пунктов. Full Conformance на этом SHA был отменён после нового push; предыдущий на `ca6f21f` прошёл.

## Измеримый срез по advancement triggers

Инвентаризация исходников 26.3 (`python3 .ci/advancement_trigger_audit.py`) нашла **58 зарегистрированных trigger ID**; в основном dispatcher Steel разрешены **6**, каждый с ограничениями предикатов. Остальные 52 там не разрешены, включая специальный `impossible`; отдельные упоминания и вызовы в исходниках не доказывают работающий критерий. Срез не является процентом паритета или оценкой всех 19 пунктов. Для воспроизведения требуется сгенерированный `minecraft-src` целевой версии.

Это результат конкретной выборки, а не доказательство полного паритета генерации.
- Ранее реализованные проверки advancement не работали с обычными vanilla-критериями: генератор заменял их на `impossible`. На `db778bd` генератор сохраняет идентификатор и условия; сквозной тест `husbandry/wax_on` и [точечные регрессии](https://github.com/Greston897/SteelMC/actions/runs/44966749941) прошли. Player и component-предикаты здесь намеренно не поддерживаются. Остальные триггеры, в том числе inventory, using-item и tick/location, пока намеренно отключены во избежание ошибочной выдачи необратимого прогресса. Критерий проверяется после успешного помещения игрока в целевой мир, а не до него. Результат подготовки не публикуется при отмене и ошибках; настройки игровых правил также читаются вне блокировки мира. Функции и function tags читаются также из ZIP без распаковки; overlays и filters для ZIP и каталогов пока отклоняются, чтобы не публиковать неверный набор функций. Это только часть функции reload, а не общая транзакция datapack или реализация enable/disable. Сохранение выбора, поддержка overlays и filters, все остальные reloadable ресурсы и онлайн-синхронизация остаются незавершёнными.

## Правило изменения процента

Менять балл только после конкретного исправления и проверки, привязанной к версии и границе пункта. Для пунктов «все» сначала нужен исчерпывающий измеримый перечень; прохождение части тестов не доказывает весь пункт. Ни один балл в этом аудите не повышен.
